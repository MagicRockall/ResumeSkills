# Resume Version Manager

## When to Use This Skill

Use when user has multiple resume versions to manage or is applying to many roles. Mentions: "resume versions", "master resume", "which resume did I send".

## The Master Resume Concept

One comprehensive document with ALL experiences, ALL bullet points ever written, every achievement. This is your source of truth — never edit it for applications, always copy first.

## File Naming Convention

`LastName_Role_Company_MonthYear.pdf`
Examples:
- `Smith_ProductManager_Google_Jan2024.pdf`
- `Smith_SWE_Stripe_Feb2024.pdf`
- `Smith_Master_Resume_v3.docx`

## Workflow

Master Resume → Copy to new file → Analyze JD → Select relevant bullets → Tailor → Save with proper name → Update application tracker

## Application Tracker Columns

Company | Role | Resume Version Used | Date Applied | Status | Notes

## Best Practices

- ✅ Always work from master as source
- ✅ Use consistent naming conventions
- ✅ Track which version went where
- ✅ Keep master updated after new projects/roles
- ✅ Archive (don't delete) old versions
- ❌ Never edit master directly for applications
- ❌ Never use vague names like "resume_final_v2"
